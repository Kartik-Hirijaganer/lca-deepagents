# Deploying the Agent in Slack

`agent.py`, `instructions.md`, `sandbox/`, and `skills/` cover the core of an MDA project. A couple more pieces are opt-in: you add a file, MDA discovers it automatically at deploy time, and a new capability turns on. Here's the one worth knowing about: putting the agent in Slack.

## Identity: who's allowed to call the agent

```python
# identity.py
from managed_deepagents import define_identity, auth

identity = define_identity(auth=auth.langsmith_api_key())
```

`identity.py` declares who's allowed to call a deployment. It matters most once the agent needs to receive events from somewhere else, like Slack: an inbound message needs an identity to attribute it to, so `channels/` and `identity.py` go together in practice.

<details>
<summary>Other ways to authenticate callers</summary>

`auth.langsmith_api_key()` verifies a caller's LangSmith workspace API key; it's the simplest option, but everyone with the key shares the same threads. `auth.supabase()` is the other `auth.*` option on `define_identity`, for giving signed-in end users their own private threads. See the [identity docs](https://docs.langchain.com/langsmith/python/managed-deep-agents-identity) for details.

</details>

## Channels: putting the agent somewhere real

```python
# channels/slack.py
from managed_deepagents import channels

channel = channels.slack(
    name="chinook-sales-assistant",
    description="Answers questions about Chinook sales and drafts the weekly newsletter",
)
```

This is the same discovery pattern as `skills/`: a file that exports the right name, picked up automatically. What makes it worth calling out: MDA provisions the Slack app itself as part of `mda deploy .`. There's no bring-your-own app, no manually generated manifest, no token to copy in. Deploying walks you through authorizing the app for a workspace, and once that's done, the agent can be DM'd or `@mentioned` from inside Slack, answering with the same sandbox and skills underneath, just a different surface asking the question.

<details>
<summary>Customizing how the Slack app looks</summary>

`name` and `description` are the two fields used above; `icon` is also available if you want the Slack app's avatar to match your own branding. All three are optional; they only affect how the app displays, never whether MDA provisions it.

</details>

## The pattern across both

Notice the shape repeats: a small file, a `define_*` or `channels.*` call, module-level export, discovered by MDA without any registration step. That's deliberate. Once you've seen it for `sandbox/` and `skills/`, `identity.py` and `channels/slack.py` aren't new concepts, just the same declarative pattern applied to a new capability.

## Recap

- `identity.py` (`define_identity(auth=...)`) declares who can call a deployment. It's optional on its own, required once a channel needs to attribute inbound messages.
- `channels/slack.py` puts the agent in Slack with no bring-your-own app; MDA provisions the Slack app itself and walks you through authorizing it on deploy.
